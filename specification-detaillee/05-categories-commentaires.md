### 5.5 Répartition par catégories (P1)

Chaque fichier reçoit **une seule catégorie** : la première règle qui correspond l'emporte, dans cet ordre de priorité. Toutes les comparaisons de noms sont insensibles à la casse.

| Priorité | Catégorie | Règles |
|---:|---|---|
| 1 | générés | voir §5.5.1 |
| 2 | tests | voir §5.5.2 |
| 3 | documentation | ancêtre `docs/` ou `doc/` ; `*.md`, `*.mdx`, `*.rst`, `*.adoc`, `*.txt` ; `LICENSE*`, `CHANGELOG*`, `AUTHORS*`, `NOTICE*` |
| 4 | configuration | voir §5.5.3 |
| 5 | sources | extension présente dans la table de langages (§5.6.1), y compris HTML, CSS/SCSS/Less, SQL, Shell, Vue et Svelte |
| 6 | autres | fichiers texte non reconnus, et fichiers de données (§5.5.3) |
| 7 | inconnus | binaires et fichiers non classables |

JSON, YAML, Markdown et CSV ne sont jamais classés en « sources ». Les règles sont versionnées dans le code et documentées. Comme chaque fichier n'a qu'une catégorie, la somme des catégories est égale au total. Ne pas annoncer comme « sources utiles à l'IA » une classification incertaine.

#### 5.5.1 Fichiers générés

Un fichier est classé « généré » si l'une des règles suivantes s'applique (le chemin est testé avant le contenu) :

- **Par chemin ou nom :** `*.min.js`, `*.min.css`, `*.map`, `*.lock`, `package-lock.json`, `pnpm-lock.yaml`, `yarn.lock`, `poetry.lock`, `Cargo.lock`, `composer.lock`, `Gemfile.lock`, `go.sum`, `*.generated.*`, `*.g.dart`, `*.pb.go`, `*_pb2.py`, `*.designer.cs`, et tout fichier sous un ancêtre `__snapshots__/` ou `__generated__/`.
- **Par marqueur d'en-tête** (dès la V1) : on cherche, sans tenir compte de la casse, dans les 5 premières lignes et au plus 1 Ko, l'un des marqueurs suivants :
  - `Code generated` suivi de `DO NOT EDIT` sur la même ligne (convention Go) ;
  - `@generated` ;
  - `<auto-generated` (.NET) ;
  - `This file is automatically generated` ;
  - `Autogenerated by` ou `Generated by` suivi de `protoc`, `openapi`, `swagger`, `graphql-codegen`, `prisma`, `thrift` ou `sqlc`.
- **Minification :** une ligne de plus de 1 000 caractères parmi les 5 premières lignes d'un fichier source.

Cette lecture réutilise le tampon déjà lu pour la détection binaire : elle n'ajoute pas d'entrée-sortie.

#### 5.5.2 Tests

- **Par répertoire :** un ancêtre, à n'importe quelle profondeur, nommé `test`, `tests`, `__tests__`, `spec`, `specs`, `e2e`, `__mocks__`, `testdata` ou `fixtures`.
- **Par nom de fichier :** `*.test.*`, `*.spec.*`, `*_test.go`, `test_*.py`, `*_test.py`, `*Test.java`, `*Tests.java`, `*Test.kt`, `*Tests.cs`, `*_spec.rb`.

#### 5.5.3 Configuration et données

- **Toujours configuration :** `package.json`, `tsconfig*.json`, `jsconfig*.json`, `*.config.*`, `.*rc` et `.*rc.*`, `.editorconfig`, `.gitignore`, `.gitattributes`, `.env*`, `Dockerfile*`, `docker-compose*.yml`, `Makefile`, `*.csproj`, `*.sln`, `pom.xml`, `build.gradle*`, `Cargo.toml`, `pyproject.toml`, `setup.cfg`, ainsi que tout fichier sous `.github/`, `.vscode/` ou `.idea/`.
- **Configuration par défaut :** `*.json`, `*.jsonc`, `*.yaml`, `*.yml`, `*.toml`, `*.ini`, `*.cfg`, `*.conf`, `*.properties`, `*.xml`.
- **Exception données :** les fichiers de la ligne précédente situés sous un ancêtre `data/`, `assets/`, `i18n/`, `locales/`, `lang/` ou `public/` sont classés « autres ». Ceux situés sous `fixtures/` ou `testdata/` sont déjà classés « tests » (priorité 2).

Afficher le **volume physique analysé** et le **volume de sources classifiées** séparément. Ce second volume n'est qu'un proxy du code potentiellement pertinent pour une IA, pas une mesure objective de compréhension ou de difficulté.

### 5.6 Blancs et commentaires (P1)

Moteur **maison** fondé sur une table de syntaxes versionnée, sur le modèle de `scc`/`tokei` :

- pour chaque langage : marqueurs de commentaire de ligne, paires de commentaires de bloc, délimiteurs de chaînes ;
- un petit automate suit l'état chaîne/commentaire afin qu'un `//` à l'intérieur d'une chaîne ne soit pas compté comme commentaire ;
- environ 35 langages au départ (§5.6.1) ; `null` pour les autres, avec des totaux physiques toujours fiables.

**Ligne mixte :** une ligne contenant du code et un commentaire (`x = 1 // note`) compte comme **ligne de code**. On a toujours `codeLines + commentLines + blankLines = physicalLines`.

**Docstrings Python :** une chaîne `"""` ou `'''` qui commence une instruction (rien d'autre que des blancs avant elle sur la ligne) est comptée comme **commentaire** sur toutes ses lignes. `x = """..."""` reste du code.

**Fichiers multi-langages** (HTML, Vue, Svelte, etc.) : seule la syntaxe de commentaire du conteneur (`<!-- -->`) est appliquée. Un `//` ou un `/* */` à l'intérieur d'un bloc `<script>` ou `<style>` est compté comme code. Cette sous-estimation est documentée.

Documenter les autres limites : commentaires imbriqués (sauf Rust, Haskell et Swift, gérés), SQL dans des chaînes, heredocs.

#### 5.6.1 Table de langages V1

La table est organisée par **famille de syntaxe** : une règle par famille, puis des surcharges par langage. Ajouter un langage revient à ajouter une entrée.

| Famille | Commentaires | Langages |
|---|---|---|
| Style C | `//`, `/* */` | JavaScript, TypeScript, JSX, TSX, Java, C, C++, C#, Objective-C, Go, Rust, Kotlin, Swift, Scala, Dart, Groovy, CSS (`/* */` seulement), SCSS, Less |
| Style `#` | `#` | Python (+ docstrings), Ruby (+ `=begin`/`=end`), Shell/Bash/Zsh, Perl, R, YAML, TOML, Dockerfile, Makefile, Elixir |
| Spécifiques | — | PHP (`//`, `#`, `/* */`), PowerShell (`#`, `<# #>`), SQL (`--`, `/* */`), Lua (`--`, `--[[ ]]`), Haskell (`--`, `{- -}`), HTML/XML/SVG/Vue/Svelte (`<!-- -->`), Batch (`REM`, `::`), INI (`;`, `#`) |

Les formats sans commentaires (JSON, Markdown, CSV, texte brut) donnent `commentLines: 0` avec `blankLines` calculé ; les formats absents de la table donnent `null`. Les résultats sont confrontés à `scc` sur des corpus de test.
